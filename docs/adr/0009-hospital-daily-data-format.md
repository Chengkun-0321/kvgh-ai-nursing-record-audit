# ADR 0009：院方每日資料交換格式與自製假資料

- 狀態：提議
- 日期：2026-10-01

## 背景

院方預計 10/16 才提供資料，0924 會議護理長請我們先整理「需要院方提供哪些資料」交給資訊處。0916、0924 討論已確認：院方每天 01–02 點產出前一天的病房資料，結構為「日期 → 病患 → 該病患資料」，病患去識別；每日身體評估全部項目都送，由系統判斷異常；會診提供開立、簽收、回覆時間；給藥先限高警訊用藥。開發與驗證稽核規則也需要一份可重現、含正確與錯誤情境的假資料。

## 決策

1. **格式由我們先定義**：[hospital-data-spec.md](../hospital-data-spec.md)（v0.1.0）＋ JSON Schema（`docs/hospital-data-spec/`），交給院方資訊處照著產出。
2. **每日一個資料夾、每位病患一個 JSON**：`<YYYYMMDD>/<patient_id>.json`，另附 `manifest.json` 列出當天檔案，供完整性檢查。
3. **增量**：每天只送當天新增或修改的紀錄（修改沿用同一 ID 並帶 `last_modified_at`），歷史由本系統累積；會診在狀態改變當天送最新狀態；管路送當天現況清單。
4. **命名**：欄位用英文 snake_case（依 glossary）；臨床選項的值照院內畫面原文（中文），系統代碼用英文（`shift`、`direction`、`status`）；空白項目用 `null`。
5. **去識別**：不送姓名、病歷號、身分證、生日；病患與人員都用院方代碼。
6. **自製假資料放專案根目錄 `mock_data/` 並進版控**：4 位病患、2026-09-01～09-30，內容由人工逐筆撰寫（不用程式產生），刻意放入正確、錯誤與邊界情境，答案表寫在 `mock_data/README.md`，病患 JSON 內不放任何答案標記。

## 影響

- 好處：院方有明確規格可依循，`LocalFixtureSource` 與日後 `RelaySource` 讀同一種結構；假資料可重現、可 diff，能用來驗證平台有沒有抓到錯誤。
- 代價：院方實際能提供的欄位可能與規格不同，需再調整規格與 schema 版本；假資料情境需與答案表同步維護。
- 後續：依規格建立 `app/schemas/ingestion/`、models、migration；`MOCK_DATA_DIR` 加入 `Settings`；規格第 6 節的待確認事項需與院方確認後更新版本。
