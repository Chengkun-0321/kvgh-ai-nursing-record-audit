# ADR 0013：入院規則可單項重新稽核，週期改稱「入院時」

- 狀態：採用
- 日期：2026-11-25

## 背景

- R01、R03 的稽核週期是 `once_per_admission`：結果固定記在入院日，不管畫面選的是哪一天（ADR 0011 決策 3）。
- [ADR 0012](0012-audit-day-rules.md) 決策 3 規定這兩項完成後不可再執行：`can_run` 為 false，`run_rule` 回 409。是否提供重跑入口列為待確認。

## 問題

- 護理師在病患頁看不到 R01、R03 的「重新稽核」按鈕，入院評估修改後，或 prompt、判斷準則調整後，都無法重跑。
- 週期標籤「一次性」只說明能跑幾次，沒有說明稽核的是哪一天的紀錄，使用者看不懂；開放重跑後，這個標籤也與實際行為矛盾。

## 決策

專案負責人於 2026-11-25 決定：

### 1. 單項可重新稽核，一鍵稽核不納入

| 狀況 | `can_run` | `include_in_run_all` |
|---|---|---|
| 入院規則尚無完成結果 | 依可稽核性 | 同 `can_run` |
| 入院規則最新一列為 `COMPLETED`（非驗證失敗） | 依可稽核性（仍為 true） | false |
| 入院規則最新一列為驗證失敗的 `NEEDS_REVIEW` | 依可稽核性 | 同 `can_run` |

- `run_rule` 不再因規則已完成回 409；`RuleSettledError` 移除。所選日期未結束的 409（ADR 0012 決策 1）不變。
- 重跑新增一列 `audit_runs`，舊結果保留；病患頁與病床總覽改顯示最新一列。
- 一鍵稽核不納入已完成的入院規則，避免每次一鍵稽核都重新呼叫模型。
- 不加確認對話框：按鈕需逐項手動點擊。

### 2. 命名

- 畫面標籤 `AUDIT_CYCLE_LABELS[ONCE_PER_ADMISSION]` 由「一次性」改為「入院時」，與「每日」「有事件時」並列，都說明稽核的是哪一天的紀錄。
- 文件與註解中的「一次性規則」改稱「入院規則」（R01、R03）。
- 識別字 `ONCE_PER_ADMISSION`／`once_per_admission` 不改：值存在資料庫，改名需要 migration。

### 3. 對 ADR 0012 的修正

- 取代決策 3「一次性規則完成後不可再執行」，並關閉其待確認項目「入院評估修改後是否提供重跑入口」。

## 影響

- 病患頁的 `can_run` 與病床總覽的分母（`RuleDay.can_run`）對入院規則重新一致；ADR 0012 影響中「分母不同」一項不再存在。
- 重跑會增加結果列與模型費用，只在使用者逐項按下時發生。
- 系統仍不知道入院評估何時被修改，是否需要重跑由使用者判斷。
