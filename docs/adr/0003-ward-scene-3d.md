# ADR 0003：病房場景改用 Blender 場景模組＋React Three Fiber

- 狀態：提議
- 日期：2026-09-27

## 背景

首頁病房地圖原本以 SVG／CSS 手繪假透視，和概念圖（寫實的 3/4 俯視娃娃屋剖面）落差很大。交付醫院後，各病房的床數都不同，場景必須依床數動態產生，不能是固定的一張圖。

病床加病人已有 24 張去背圖（固定視角、判定光暈已繪入），希望沿用。

## 決策

1. **模組來源**：以 Blender 5.2 的 Python 腳本程序化建模（`frontend/scripts/blender/`），產生可拼接的場景模組 GLB（`frontend/public/models/ward/`）：
   - 床位空間：第 0 排靠後牆、其餘排靠床頭隔屏。
   - 左右側走道：含輪替擺設。
   - 前緣剖面。
   - 床下陰影貼花。
2. **光影做法**：每個模組放在 4×3 病房環境中，以 Cycles 從固定相機算圖，再把算圖投影回模型當貼圖（camera projection）。前端以無光照材質顯示，不放燈光。
   - 取代原本規劃的「光影烘焙」：相機永不旋轉，所以地板反光、柔和陰影、間接光都能直接保留，品質高於只烘漫射光。
3. **前端**：新增依賴 `three`、`@react-three/fiber`、`@types/three`（使用者核准）。
   - 相機為正交投影，yaw／pitch 由病床去背圖校準，只能平移與縮放。
   - 同一模組以 `InstancedMesh` 繪製，`frameloop="demand"`。
   - drei 已核准但不需要，未安裝。
4. **互動**：沿用 DOM 地圖控制器（拖曳、縮放、鍵盤、避開詳情卡）。
   - 病床按鈕與標籤為 DOM 疊層，確保無障礙。
   - 控制器每次重繪時同步 3D 相機並立即繪製該幀。
5. **單一來源**：`frontend/src/lib/wardKit.json` 記錄模組尺寸、相機角度與去背圖錨點，前端與 Blender 共用。
6. **版面**：整個病房一個大空間。欄排數只依床數決定，視窗寬度不參與。
7. **降級**：沒有 WebGL 或場景載入失敗時，改用 2D 病床清單。

## 影響

- **好處**
  - 畫面接近概念圖，任意床數都能自動組裝。
  - 12 個模組總計約 364 KB。
  - 醫院內網可用，完全不從 CDN 載入。
- **代價**
  - 視角被去背圖綁定（yaw 13.7°、pitch 36.5°）。要改視角必須重新生成 24 張去背圖並重跑校準。
  - 3D 場景無法 SSR，模型載入後才出現。但 DOM 病床按鈕先可操作，也不做淡入。
  - three.js 相關 chunk 約 260 KB（gzip），以動態載入與首頁主程式分離。
- **例外**
  - Blender 材質色取自 `--color-scene-*` token，但 `ward-floor` 等圖片素材與算圖光影不受 token 管理。
  - 病床座標與 CSS 變數以 Web Animations 寫入，延續既有控制器做法，不使用 React inline style。
- **後續**
  - 院方病床資料若含病室，可改為依病室分區（目前待決）。
  - 修改模組後需重新建置並遞增 `assetVersion`。
